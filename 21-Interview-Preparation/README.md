## What Interview Preparation Covers

This module is a **final revision pass** — a curated collection of interview questions across seven categories (Programming Fundamentals, OOP, DSA, SQL/Databases, Web Development, System Design, Behavioral). Per this repository's convention, this module doesn't duplicate deep, hands-on content — it indexes back to it. Wherever this repository has already built and verified a real, working demonstration of a concept, the answer here links directly to it, so a genuine claim ("verified live: ...") is always one click from the actual code and output that proved it.

## Why This Module Is Reference Content, Not Runnable Code

Unlike this repository's other modules, the subject here is revision and recall, not new hands-on implementation — appropriate for a "final pass" per this repository's own [ROADMAP.md](../ROADMAP.md). The six technical files (01-06) are markdown reference documents; the seventh (Behavioral) is necessarily prose, since behavioral questions are answered from personal experience, not code. Every technical claim that references this repository's other modules points to a lesson where that exact behavior was actually compiled, run, and verified — not merely asserted here for the first time.

## Why It Matters / Where It's Used

- **This module is the fastest way to review everything this repository has built**, organized by the categories real interviews actually use, rather than by the module structure used for learning.
- **Every linked claim is backed by real, verified evidence** — a real SQL injection exploit, a real measured race condition, a real network partition with measured data divergence, a real signed-byte corruption bug — not generic interview-prep answers detached from anything actually run.
- **Interviews at every level draw from these seven categories** — this module's structure mirrors how technical interview loops are actually organized (a coding round, a system design round, a behavioral round).

## How to Use This Module

Read each file as a rapid self-check: can you answer the question in your own words before reading the given answer? For any answer that references a linked lesson, follow the link and re-run that lesson's actual code if the concept feels shaky — seeing the real, live-verified output again is more effective revision than re-reading a description.
